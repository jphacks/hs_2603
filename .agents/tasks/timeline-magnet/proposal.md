# タイムラインのマグネット（スナップ）機能の案

- 調べたもの: ブランチ feat/ikumu1、HEAD eaac4b6。指示書の時点で未コミットだった赤い線の変更（timelinewidget.cpp）と `.agents/tasks/timeline-playhead-left/` は eaac4b6 にコミット済みで、作業ツリーに変更はない（`git status --porcelain` が空）。中身は指示書の前提と同じなので、行番号は今のファイルのもの。
- コードを読んだだけで、ビルド・起動・操作はしていない。【確認】はコードを読んで確かめたこと、【推測】は動かしていないので予想していること。
- 用語: スナップ（吸着・マグネット）＝ドラッグ中の位置が決まった点に近づいたら、その点にぴったり合わせること。しきい値＝どこまで近づいたら吸着するかの距離。pps＝1 秒あたりのピクセル数（拡大率）。

## 0. まとめ

- 今のスナップ【確認】: 効くのはテキストとオーディオの移動と長さの変更だけ。吸着先は 0:00、押したときの赤い線の位置、ビデオのクリップの境目、ほかのテキストとオーディオの端。しきい値は画面上で 8px（拡大率に関係なく同じ）。目印・オン/オフ・一時的に外す方法はない。キリのいい秒は吸着先にない。赤い線のドラッグ、クリップの長さ変更、ドロップ、ダブルクリックには効かない。
- 不具合【確認（コードを読んだ限り）】: テキストやオーディオを動かすとき、右端（終わり）は、左端も同時に吸着できるときしか吸着しない（1 章）。
- 案
  - 案A（小）: 赤い線のドラッグだけ、目盛りの数字の位置（キリのいい秒）と 0:00・終わりで止まる。
  - 案B（中、おすすめ）: 案A＋テキスト・オーディオもキリのいい秒で止まる。磁石ボタンと N キーでオン/オフ、ドラッグ中に Alt を押す間だけ外す。
  - 案C（中〜大）: 案B＋クリップの右端の長さ変更・ライブラリからのドロップ・ダブルクリックでのテキスト追加にも効かせる。
  - 案D（中）: 間隔を拡大率で変えず、いつも 1 秒ごと（または選べる）にする。A〜C の「間隔の決め方」を差し替える案。
- おすすめ: 案B を段階的に作る。最初は案A の形（timelinewidget.cpp/.h だけ）で止まり具合を試し、次にテキスト・オーディオ、最後にオン/オフのボタンとキー。
- ユーザーへの質問（7 章）: 止まってほしい操作 / キリのいい秒の間隔 / 端にも止まるか / オン/オフの方法。

## 3. 目盛りと「キリのいい秒」

paintRuler は `kSteps`（294）から「1 間隔が 70px 以上になる一番小さい値」を数字の間隔にし（301-307）、その 1/5 を細かい線にする（308）【確認】。拡大率ごとに計算すると次のとおり。

| 拡大率（px/秒） | 数字の間隔 | 細かい線 |
|---|---|---|
| 140〜400 | 0.5 秒 | 0.1 秒 |
| 70〜139 | 1 秒 | 0.2 秒 |
| 35〜69（起動したときの 60 はここ。editor.h:141） | 2 秒 | 0.4 秒 |
| 14〜34 | 5 秒 | 1 秒 |
| 7〜13 | 10 秒 | 2 秒 |
| 4.7〜6.9 | 15 秒 | 3 秒 |
| 4〜4.6 | 30 秒 | 6 秒 |

- 数字の位置は 70px 以上離れているので、しきい値 8px（前後で 16px）なら止まる範囲は全体の 23% 以下。細かい線は 0.4 秒や 3 秒のようにキリがよくないうえ、間隔が 14〜40px と近いので、吸着先にすると止まってばかりになる。→ 吸着先は「数字の位置」にする。
- 数字の位置は 0.5 秒の倍数なので、24/30/60fps のどれでもフレームの境目になる（細かい線の 0.1 秒は 24fps だと 2.4 フレームでずれる）。
- 1 秒ごとに固定すると、起動したときの拡大率では 1 秒の所に線がない（線は 0.8 秒と 1.2 秒）。縮小して 1 秒が 16px より狭くなると、どこにいても 1 秒の点に吸い付き、秒の間に置けなくなる。

## 4. 案

### 案A: 赤い線だけ、目盛りの数字の位置で止まる（作業量: 小）

- 仕組み: 赤い線のドラッグ（`Drag::Scrub`、押した瞬間も含む）で、マウスの時刻に一番近い数字の位置（`round(t / 間隔) * 間隔`）が 8px 以内ならそこへ seek する。0:00 とビデオの終わりも吸着先にする。間隔は paintRuler の計算（301-307）を `rulerStep()` に切り出して共有し、目盛りの数字とずれないようにする。テキストとオーディオの今の吸着は変えない。
- 操作と見え方: 目盛りをドラッグすると、赤い線が「0:02」「0:04」の所で少し止まる。さらに 8px 動かすと離れて、またマウスについてくる。止まっている間は、その数字と線を黄色（挿入線と同じ色、581）にする。Alt を押しながらドラッグすると止まらない（今あるテキスト・オーディオの吸着も、Alt を押している間は外れる）。止まった所から 1 フレームずらすときは ←→。
- 良い点: 頼まれたことに一番近い。変更は timelinewidget.cpp/.h だけ。編集データに触らないので、元に戻すにも関係しない。
- 悪い点: テキストやオーディオはキリのいい秒に止まらない。止めっぱなしにするスイッチがない（Alt だけ）。
- 変更するファイル: timelinewidget.h（`rulerStep()`、吸着中の時刻を持つ `std::optional<double>` のメンバー）、timelinewidget.cpp（paintRuler、mousePressEvent 652、mouseMoveEvent 690、mouseReleaseEvent 777-790 で目印を消す）。

### 案B: 案A＋テキスト・オーディオ＋マグネットのボタン（作業量: 中、おすすめ）

- 仕組み: 今の `snap()` を広げて吸着の計算を 1 つにし、赤い線・テキスト・オーディオで同じものを使う。吸着先は「内容の点」（0:00、ビデオの終わり、クリップの境目、テキストとオーディオの端、テキストとオーディオのときは赤い線）と「数字の位置」。内容の点を先に探し、なければ数字の位置（5 章の 1）。移動は、左端と右端のうち実際に吸着したほうを使うように直す（1 章の不具合）。
- 操作と見え方:
  - タイムラインのツールバーの右側、縮小ボタンの左に磁石のボタン。オンのときは押された見た目（theme.cpp:52 の `QToolButton:checked`）。アイコンを青（`theme::accent`）にするとさらに見分けやすい。ツールチップは「スナップ (N)」。N キーと「表示」メニューの「スナップ」（チェック付き）でも切り替えられる。起動したときはオン。
  - テキストやオーディオをドラッグすると、どちらかの端がキリのいい秒・赤い線・ほかの端に近づいたときに止まり、その時刻に黄色い縦線がトラック全体に出る。
  - Alt を押している間は止まらない。オフにすると、今ある吸着（端と赤い線）も止まる。
- 良い点: どの操作でも同じ止まり方。今の snap() を使い回せる。ずっとオフにもできる。ほかの編集ソフトと同じような操作（8 章）。
- 悪い点: 案A より変えるファイルが多い。オンのままだと秒のすぐ近くにはマウスで置けない（起動したときの拡大率・30fps で前後 4 フレームほど。Alt か ←→ で合わせる）。テキストとオーディオの動きが少し変わる（キリのいい秒と右端でも止まる）。
- 変更するファイル:
  - `native/src/ui/timelinewidget.cpp/.h`: 案A の内容、`snapPoints`（248-266）と `snap`（268-279）、ItemMove（720-731）、ItemTrim（732-770）、ツールバー（862-895）のボタン。
  - `native/src/core/editor.h/.cpp`: `snapEnabled()`・`setSnapEnabled()`・`snapChanged` シグナル。拡大率の `pxPerSec_`・`setPxPerSec`・`zoomChanged`（editor.h:64-65、110、141、editor.cpp:191-196）と同じ作り。編集データ（ProjectData）には入れない。

  - `README.md`: できること（70）とショートカットの表（86-）。

### 案C: 全部の操作に効かせる（作業量: 中〜大）

- 仕組み: 案B に次を足す。

  - ライブラリからのドロップ（819-852）: オーディオの開始位置を吸着させ、ドラッグ中に黄色い縦線を出す。ビデオは今のまま（挿入位置）。

- 悪い点: 変わる動きが多く、確かめる範囲が広い。ドロップ中の線は新しく作る。クリップの長さ変更は後ろが詰まる動きなので、何に合わせるかがわかりにくい。

### 案D: 決まった秒数ごと（作業量: 中）

- 仕組み: 数字の位置の代わりに、いつも 1 秒ごと（または磁石ボタンの小さなメニューで 0.5 / 1 / 5 秒から選ぶ）に止まる。1 秒の間が 40px より狭いときは止めない（止まりすぎるため）。A〜C のどれとも組み合わせられる。
- 良い点: 拡大率に関係なく同じ秒で止まるのでわかりやすい。
- 悪い点: 起動したときの拡大率では 1 秒の所に目盛りの線がなく、見えない所で止まる（3 章）。縮小すると止まらない。例えば 30 秒の動画を「全体を表示」にすると 1 秒が 30px 台になり、止まらない【推測: 画面の幅による】。選ぶメニューを作ると作業が増える。
- 変更するファイル: 選んだ案のもの＋間隔を持つ場所（editor.h/.cpp）と選ぶ UI（timelinewidget.cpp）。

## 5. どの案でも決めること（おすすめの決め方）

1. 吸着先が複数近いとき: 内容の点（0:00、終わり、境目、端、赤い線）を先に探し、8px 以内になければ数字の位置。同じ種類の中では一番近いもの。移動では左右の端のうち、ずれが小さいほう。理由: 数字の位置はどこにでもあるが、端同士がぴったり合うほうが大事（すき間や 1 フレームの重なりを防ぐ）。
2. しきい値: 今と同じ 8px。ピクセルで決めるので拡大率に関係なく同じ感じになる。強すぎたら 6px にする。一度止まったら離れるのに多めに動かす作り（ヒステリシス）は、最初は入れない。
3. 拡大率と単位: 3 章の数字の間隔を使う（paintRuler と同じ計算）。ドラッグ中に Ctrl+ホイールで拡大率が変わったら、次にマウスが動いたときの間隔を使う。
4. フレーム: 数字の位置は 24/30/60fps でフレームの境目だが、念のため `frameRound`（timeline.cpp:29）を通す。吸着しなかったときの時刻は今と同じでそろえない（そろえるのは別の機能）。
5. 元に戻す: 吸着は `updateText`・`updateAudio` に渡す値を変えるだけ。`merge_`（645）と `endMerge()`（788）はそのままなので、1 回のドラッグは今と同じく 1 回の操作。赤い線のドラッグは今も履歴に残らない。オン/オフは編集データではないので、履歴・「変更あり」・自動保存に入らない。
6. ←→・再生中・followPlayhead: `Editor::seek` は変えない（←→、Home/End、プレビューのボタン、クリップの長さ変更のプレビューでも使うため）。吸着は TimelineView の中だけで計算する。押すと再生は止まり（648）、followPlayhead は再生中だけ（154）なので、再生中の動きは変わらない。
7. オン/オフの保存と初期値: 起動したときはオン（今の吸着がいつも効いているのと同じ）。保存しない。README に「設定ファイルやレジストリには何も書かない」とあり（README.md:226）、ソースにも QSettings はない。保存するなら設定ファイルを新しく作り、README も直す必要がある（QSettings は Windows では標準でレジストリに書く）。
8. キーボードだけで使う人: キーの操作は変わらない。オン/オフは N キーと「表示」メニュー（Alt+V）で切り替えられ、メニューにチェックが付く。ツールバーのボタンは今のほかのボタンと同じく Tab で選べない（widgets.cpp:37 `Qt::NoFocus`）ので、メニューを用意する。
9. タッチパッド: マウスと同じイベントなので同じく効く。指では細かく合わせにくいので、吸着が役に立つ。Alt を押しながらが難しければ N かボタンで切る。ピンチでの拡大縮小は今もなく、変わらない。
10. キーのぶつかり: N は今は使っていない（S は分割、T はテキスト、Ctrl+N は新規）。Alt はドラッグで使っていない（handleKey は Ctrl・Alt 付きのキーを無視する、445）。Ctrl（拡大縮小。ほかのソフトではコピー）と Shift（←→ の 1 秒移動と縦スクロール。「大きく動く」の意味）は意味がぶつかるので使わない。【推測】Windows では Alt だけを押して離すとメニューが選ばれることがあるが、ドラッグ中はマウスが動くので起きにくい。実機で確かめる。
11. クリック: 目盛りや空いた所を押した瞬間（652）も吸着させる。クリップやテキストを押して離したときに赤い線が動く所（781、783）は今のまま。

## 6. おすすめと進め方

案B を次の順で作る。各段階でビルドできて使える状態にする。

1. 最初の形（＝案A）: 吸着の計算を 1 つの関数にまとめ、赤い線のドラッグを数字の位置・0:00・終わりで止める。目盛りの強調と Alt。テキストとオーディオはまだ数字の位置を使わない（今の動きのまま）。変更は timelinewidget.cpp/.h だけ。ここで止まり具合（8px）を触って決める。
2. テキストとオーディオ: 同じ関数で数字の位置にも止める。移動の右端の不具合を直す。黄色い縦線を出す。赤い線もクリップ・テキスト・オーディオの端に止める。
3. オン/オフ: 磁石ボタン、N キー、表示メニュー、ショートカット一覧、README。
4. 必要になったら: 案C の 3 つ、オン/オフの保存。

理由: 「キリがいい秒数でちょっと止まる」に一番近いのは赤い線で、最初の形が小さく試しやすい。今の snap() を広げるので吸着の考え方が 1 つにまとまり、オン/オフや Alt も 1 か所で効く。目盛りの数字の位置で止まるので、どこで止まるかが目で見える。ボタン・N・Alt はほかのソフトと同じ考え方（8 章）。

計算のイメージ（実装はしていない）:

```cpp
// 吸着の結果。guide は目印を描く時刻（吸着しなかったときは空）
struct SnapResult { double t; std::optional<double> guide; };

SnapResult TimelineView::snapTime(double t, const std::vector<double>& points, bool useGrid) const {
  const double range = kSnapPx / pps();  // 8px を秒に直す
  // 1) 内容の点（0:00・終わり・境目・端・赤い線）を先に探す
  double best = t, bestD = range;
  for (double p : points) {
    if (std::abs(p - t) < bestD) { best = p; bestD = std::abs(p - t); }
  }
  if (bestD < range) return {best, best};
  // 2) なければ目盛りの数字の位置（paintRuler と同じ間隔）
  if (useGrid) {
    const double step = rulerStep();
    const double g = frameRound(std::round(t / step) * step, editor().project().settings.fps);
    if (g >= 0 && std::abs(g - t) < range) return {g, g};
  }
  return {t, std::nullopt};
}
```
